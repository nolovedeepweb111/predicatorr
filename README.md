# Predicatorr — прогнозы на Dota-миксеры

Сайт для прогнозов по PARI Mixer Cup и супермиксерам (WINLINE, PARI Super).
История матчей берётся из публичного бэкапа сборщика
[pari-mixer-scraper](https://github.com/nolovedeepweb111/pari-mixer-scraper).

Что умеет:

1. **Прогноз игры.** Выбираете две команды, по желанию — героев каждому игроку.
   Сайт показывает победителя и вероятность (до драфта и с драфтом), честные
   коэффициенты и разбор: из чего сложилась оценка. Драфт учитывает мету и
   матчапы героев на высоком рейтинге (STRATZ) и то, сколько каждый игрок
   играл на своём герое в лиге и в рейтинге (OpenDota).
2. **Сравнение с PARI.** Линия Dota 2 подтягивается сама и сопоставляется с
   командами турнира. Для каждого матча — вероятность букмекера без маржи, наше
   ожидание на 100 ₽ и размер ставки по Келли. Ставки пишутся в журнал и
   закрываются сами, когда приходит результат. Если линия недоступна,
   коэффициенты вводятся вручную.
3. **Замены.** Кнопка «Замена» → кто выбыл → поиск того, кто пришёл (по всем
   игрокам из истории и очереди на замену) → «Сохранить». Прогнозы сразу
   считаются по новой пятёрке. Замену можно отменить. Когда источник сам узнает о
   той же замене, запись просто перестаёт действовать.

## Быстрый старт

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
python -m predicator serve          # http://127.0.0.1:8000
```

При первом запуске сайт скачает бэкап (около 2 МБ) и за пару секунд обучит
модель. Дальше раз в 2 минуты сайт проверяет, не изменился ли бэкап, и опрашивает
mixer-cup (составы, замены, результаты). Раз в 15 минут ещё подтягивает мету,
матчапы и историю игроков. Кнопка в правом верхнем углу обновляет всё сразу.

Из терминала:

```bash
python -m predicator predict "2hjmen" "afka"   # прогноз по названиям команд
python -m predicator backtest                  # проверка модели на прошлых кубках
python -m predicator sync                      # один проход обновления данных
python -m predicator import backup.json        # загрузить бэкап из файла
```

## Установка на сервер

Нужен сервер с Ubuntu 22.04+ или Debian 12 и домен, который указывает на его
IP (например, бесплатный DuckDNS). Одна команда от root:

```bash
curl -fsSL https://raw.githubusercontent.com/nolovedeepweb111/predicatorr/HEAD/deploy/install.sh \
  | sudo bash -s -- mixer-predicts.duckdns.org
```

Скрипт [`deploy/install.sh`](deploy/install.sh) ставит пакеты, заводит
системного пользователя `predicatorr` и кладёт код в `/opt/predicatorr`. Потом
он поднимает службу systemd, настраивает nginx с HTTPS от Let's Encrypt,
генерирует пароль на сайт и в конце печатает адрес и пароль. Пароль потом можно
посмотреть командой `sudo grep PASSWORD /opt/predicatorr/.env`.

Скрипт рассчитан на сервер, где уже работают другие сайты:

- порт выбирает сам, начиная с 8100, и пропускает занятые;
- чужие конфиги nginx и сертификаты не трогает;
- nginx не перезапускает, а перечитывает, и только после успешного `nginx -t`;
- если домен уже обслуживает другой сайт nginx, установка останавливается.
  Чтобы заменить тот сайт нашим, запустите с `PREDICATOR_TAKEOVER=1`: старый
  сайт отключится, но его файл останется;
- если порты 80/443 держит не nginx, а другой веб-сервер, установка
  остановится до любых изменений.

**Обновления ставятся сами.** Раз в 5 минут сервер проверяет основную ветку на
GitHub, и если там новый код, ставит его и перезапускает сайт
([`deploy/update.sh`](deploy/update.sh)). Если новая версия не поднялась за
полторы минуты, сервер возвращает прежнюю и больше этот коммит не пробует.
Журнал: `journalctl -u predicatorr-update`. Выключить:
`sudo systemctl disable --now predicatorr-update.timer`.

Обновить вручную или поправить установку — тот же скрипт ещё раз:
`sudo bash /opt/predicatorr/deploy/install.sh`. База, пароль и домен сохранятся.

Журнал сайта — `journalctl -u predicatorr -f`. Если сертификат не выпустился,
проверьте, что домен указывает на сервер, а порты 80 и 443 открыты, и запустите
скрипт ещё раз.

## Настройки (`.env` или переменные окружения)

| Переменная | По умолчанию | Что это |
|---|---|---|
| `PREDICATOR_DB` | `var/predicator.sqlite3` | файл базы |
| `PREDICATOR_HOST`, `PREDICATOR_PORT` | `127.0.0.1`, `8000` | где слушать |
| `PREDICATOR_PASSWORD` | пусто | пароль на сайт (HTTP Basic) |
| `PREDICATOR_SYNC_MINUTES` | `15` | полный проход (с метой, матчапами, историей игроков); `0` — только по кнопке |
| `PREDICATOR_FAST_SYNC_SECONDS` | `120` | быстрый проход между полными: бэкап (если изменился), mixer-cup, ставки; `0` — без него |
| `PREDICATOR_BACKUP_URL` | бэкап pari-mixer на GitHub | откуда брать историю |
| `PREDICATOR_BACKUP_TOKEN` | пусто | токен локальной выгрузки pari-mixer (заголовок `X-Export-Token`) |
| `PREDICATOR_BACKUP_FALLBACK_URL` | бэкап на GitHub | запасной источник, если основной не отвечает |
| `PREDICATOR_MIXER_LIVE` | `1` | опрашивать API mixer-cup (составы, расписание) |
| `PARI_ENABLED` | `1` | загружать линию PARI |
| `PARI_HOSTS` | три зеркала `line-*.pb06e2-resources.*` | адреса линии через запятую |
| `PARI_SCOPE_MARKET` | `2300` | параметр линии PARI |
| `PARI_CACHE_SECONDS` | `60` | не чаще раза в N секунд |
| `STRATZ_TOKEN` | пусто | ключ STRATZ для меты и матчапов; удобнее ввести на сайте |
| `PREDICATOR_EXTERNAL` | `1` | качать мету, матчапы и историю игроков (STRATZ, OpenDota) |

Банк, доля Келли, потолок ставки и порог перевеса настраиваются на странице
«Ставки».

## Свежая история с pari-mixer

История матчей приходит из бэкапа сборщика pari-mixer. Ветку `data-backup` на GitHub
он обновляет раз в 3–6 часов, поэтому в идущем кубке форма команд отстаёт: по проверке
на прошлых кубках опоздание на 3 часа стоит 0.7 п.п. точности, на сутки — 1.2 п.п.

Если pari-mixer работает на том же сервере, он может отдавать ту же выгрузку локально и
по токену. Что для этого сделать в pari-mixer, описано в
[docs/pari-mixer-export.md](docs/pari-mixer-export.md). После этого в `.env`:

```
PREDICATOR_BACKUP_URL=http://127.0.0.1:8000/api/export/backup
PREDICATOR_BACKUP_TOKEN=<тот же токен, что EXPORT_TOKEN у pari-mixer>
```

Сайт спрашивает выгрузку раз в 2 минуты с `If-None-Match`, так что неизменившийся бэкап
не скачивается. Если локальная выгрузка не отвечает, история берётся с GitHub, а на
странице «Модель» видно, откуда она пришла и когда была последняя игра. Матчи, у которых
ещё нет золота и убийств (их OpenDota дозаполняет позже), идут в результаты и форму, но
не в долю золота.

## Модель

Три слоя. Каждый проверен протоколом из заметки: обучение без одного кубка,
признаки игроков — только по играм до начала кубка, форма и драфт — только по
играм раньше прогнозируемой.

1. **Оценка состава** — четыре признака пятёрки по играм в прошлых кубках: доля
   золота, Эло сильнейшего, доигрываемость, суммарный MMR. Нормируются внутри
   кубка, веса — гребневая регрессия (λ = 60).
2. **Форма в идущем кубке.** После каждой игры рейтинг состава сдвигается на
   0.35 × (результат − ожидание): победа над сильным весит больше победы над
   слабым. Игра засчитывается пропорционально (совпавших игроков / 5)², поэтому
   команда после замен опирается на свою новую пятёрку, а не на чужие результаты.
3. **Драфт** — логистическая поправка поверх оценки до драфта. Признаки
   (разность команд A и B):
   - сила героя в нашей лиге (сглаженный винрейт) и опыт игрока на нём в лиге;
   - мета: винрейт героя на Divine+Immortal за последние 8 недель (STRATZ);
   - матчапы: насколько герои A выигрывают у героев B сверх ожидаемого, и
     синергия героев внутри команды — там же, миллионы игр в неделю;
   - опыт игрока на герое в рейтинге (OpenDota): игры за последние полгода
     идут целиком, более старые — с весом 0.3.

   Всё считается на момент матча: для прошлых игр берутся только недели до них.
   Незаполненные герои считаются средним пиком, поэтому драфт можно вводить по
   мере пиков. На странице прогноза видно, сколько процентных пунктов дал каждый
   признак и какие матчапы самые заметные.

Проверка на 7 кубках (2097 игр):

| Модель | Угадано | Logloss |
|---|---|---|
| Монетка | — | 0.693 |
| Модель из заметки (состав + зачтённые победы) | 66.8% | 0.609 |
| Только состав | 63.9% | 0.634 |
| Состав + форма с учётом соперника (до драфта) | 67.2% | 0.603 |
| + драфт только по нашей лиге | 67.6% | 0.599 |
| + драфт: лига, мета, матчапы, опыт в рейтинге | **69.2%** | **0.584** |

Самый сильный признак драфта — матчапы, за ним опыт игрока на герое в
рейтинге и мета. Калибровка ровная: когда модель даёт фавориту 70–80%, он
выигрывает 75% таких игр. Самые уверенные прогнозы (больше 90%) чуть
самоувереннее факта, поэтому вероятность ограничена 93%. Подробности и график —
на странице «Модель».

Что пробовали и не взяли:

- матчапы и синергии по играм самой лиги (2 тыс. игр на 127 героев — слишком
  редкая матрица; матрица с высокого рейтинга работает);
- винрейт игрока на герое в лиге, в том числе с затуханием старых игр: у
  пары «игрок — герой» в среднем две игры, это шум, а не сигнал; опыт
  (сколько игр) полезнее винрейта;
- винрейт игрока на герое в рейтинге поверх опыта — прибавки нет;
- несовпадение роли игрока и героя, поправку за сторону (свет/тьма заранее не
  известны, и выигрыш был меньше 0.001 logloss).

## Мета, матчапы и история игроков

- **STRATZ** (нужен бесплатный ключ с [stratz.com/api](https://stratz.com/api)):
  винрейты героев и матрица матчапов/синергий на Divine+Immortal по неделям.
  Ключ вводится на странице «Модель» → «Источники данных» (хранится только в
  базе на сервере и обратно не показывается) или задаётся `STRATZ_TOKEN` в
  `.env`. STRATZ пускает с одного ключа не больше двух IP за 15 минут, поэтому
  ключ должен работать только на сервере.
- **OpenDota** (без ключа): сколько игр и побед у человека на каждом герое в
  рейтинге за всю карьеру и за полгода. Если история скрыта, признак у игрока
  нулевой — как у среднего.

Скачивается понемногу при каждом фоновом обновлении: мета раз в сутки,
матчапы — по три недели за проход (свежие первыми), игроки — по 30 за проход
(сначала текущие составы), каждый раз в неделю. С нуля всё подтягивается за
несколько часов; модель переобучается сама по мере поступления данных.
Состояние — на странице «Модель».

## Линия PARI

Сайт PARI берёт линию из открытого JSON, и мы читаем его же:

```
GET https://line-lb51-w.pb06e2-resources.com/events/listBase?lang=ru&scopeMarket=2300   полный снимок
GET https://line-lb51-w.pb06e2-resources.com/events/list?lang=ru&version=V&scopeMarket=2300   изменения
```

Исход «П1» — фактор 921, «П2» — 923. Берутся только Dota-турниры. Команды
сопоставляются по названию: регистр, приставка «Team», смесь кириллицы и
латиницы не мешают, «Команда A» ищется по букве команды. Полный снимок весит
несколько мегабайт, поэтому он скачивается раз в три часа, а между ними — только
изменения. Если сервер маленький, выключите загрузку (`PARI_ENABLED=0`) и
вводите коэффициенты руками.

Проверить, что линия доступна с вашего сервера:

```bash
curl -s --compressed -H 'Origin: https://pari.ru' \
  'https://line-lb51-w.pb06e2-resources.com/events/list?lang=ru&version=0&scopeMarket=2300' | head -c 300
```

## Ставки

Ставка считается выгодной, если наша вероятность × коэффициент − 1 не меньше
порога (по умолчанию 3%). Размер — четверть Келли, но не больше 5% банка.
Модель ошибается примерно в каждой третьей игре, поэтому ставки — это риск, и
журнал нужен, чтобы видеть, работает ли перевес на дистанции (строки «Прибыль»
и «Ожидалось по модели»).

## API

Документация открывается на `/api/docs`. Основное:

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/status` | готовность модели, состояние источников |
| GET | `/api/teams?tournament_id=` | составы с оценками |
| POST | `/api/predict` | прогноз: команды, составы, герои, коэффициенты |
| GET | `/api/odds` | линия PARI с прогнозами и ожиданием |
| GET | `/api/players/search?q=` | поиск игроков и очереди |
| POST / DELETE | `/api/rosters/change` | замена / отмена замены |
| GET / POST / PATCH / DELETE | `/api/bets` | журнал ставок |
| GET | `/api/backtest` | проверка модели |
| PUT | `/api/settings/stratz-token` | сохранить или удалить ключ STRATZ |
