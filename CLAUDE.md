# Predicatorr — карта проекта

Сайт прогнозов по Dota-миксерам: Python (FastAPI, SQLite), фронтенд на чистом
JS-модулях без сборки. Интерфейс и тексты — на русском.

## Где что

| Файл | Зачем |
|---|---|
| `predicator/config.py` | настройки из env/.env, три копии mixer-cup и сдвиги номеров турниров |
| `predicator/db.py` | схема SQLite (история из бэкапа + наши таблицы: замены, ставки, линия) |
| `predicator/importer.py` | импорт `backup.json` донора, обновление только при изменении (sha256) |
| `predicator/dataset.py` | история в памяти: `Match` с пятёрками, доля золота, место по фарму |
| `predicator/features.py` | `History` (агрегаты, Эло K=24), признаки состава, зачтённая форма |
| `predicator/model.py` | три слоя модели и обучение (`train`) |
| `predicator/live.py` | живые игры из pari-mixer: привязка к командам кубка, герои по игрокам (предварительные — по опыту) |
| `predicator/external.py` | STRATZ (мета, матчапы, синергии) и OpenDota (опыт игроков в рейтинге): загрузка и признаки драфта на момент матча |
| `predicator/backtest.py` | проверка без одного кубка, отчёт |
| `predicator/service.py` | прогноз для живых составов (`PredictorService`), кэш контекста кубка, честный пересчёт сыгранных игр (`played_games`) |
| `predicator/rosters.py` | составы турнира, ручные замены, поиск игроков |
| `predicator/mixercup.py` | GraphQL mixer-cup: активный турнир, команды, игры |
| `predicator/pari.py` | линия PARI: снимок + изменения, сопоставление названий команд |
| `predicator/bets.py` | маржа, ожидание, Келли, журнал, автозакрытие ставок |
| `predicator/paper.py` | эксперимент: семь стратегий виртуальных ставок, решения раз и навсегда, отчёт |
| `predicator/sync.py` | фоновый поток: быстрый проход раз в 2 мин (бэкап по ETag → mixer-cup → ставки), полный раз в 15 мин (+ внешние данные) |
| `predicator/web.py` | API и раздача фронтенда |
| `predicator/static/` | `index.html`, `app.css`, `js/*.js` (страницы predict, schedule, results, rosters, bets, paper, model) |
| `tests/` | pytest на синтетическом бэкапе (`tests/synthetic.py`), сеть не нужна |
| `deploy/install.sh` | установка/обновление на сервере: systemd, nginx + Let's Encrypt, пароль |
| `deploy/update.sh` | автообновление по таймеру: новый коммит → установка → проверка → откат |
| `docs/pari-mixer-export.md` | что нужно от pari-mixer: локальная выгрузка по токену вместо GitHub, живой драфт |

## Правила, без которых данные врут

- Номер турнира глобальный: PARI +0, WINLINE +20000, PARI Super +30000.
- Steam `team_id` переиспользуется между кубками и неделями — команду текущего
  кубка определяет `mixer_uuid` (ключ `team_key`), форма считается по
  пересечению пятёрок, а не по `team_id`.
- `players.team_id` — всегда сегодняшний состав; прошлые составы — только из
  `match_players`.
- У старой копии mixer-cup (`api.mixer-cup.gg`) нет полей недель — не добавлять
  их в запросы к ней.
- Внешние признаки берутся только по полным неделям до матча
  (`ExternalData._window`); иначе бэктест подсматривает в будущее.
- Ключ STRATZ пускают не больше чем с двух IP за 15 минут: им пользуется только
  сервер, из песочницы его не дёргать. Хранится в таблице `settings` или в
  `.env`, в репозиторий не попадает.
- Бэкап pari-mixer на GitHub отстаёт на 3–6 часов (Actions по расписанию). Свежая
  история — из локальной выгрузки `PREDICATOR_BACKUP_URL` + `PREDICATOR_BACKUP_TOKEN`;
  токен уходит только на этот адрес, никогда на запасной.
- Установщик читает из `/etc/pari-mixer/env` только `EXPORT_TOKEN` и ничего там не
  меняет. Ручки `/api/export/*` pari-mixer закрыты снаружи — ходить на `127.0.0.1:8000`.
- В лайве перевес считается только до горна и с полным драфтом (`/api/predict`
  спрашивает время игры у pari-mixer сам, клиенту не верит).
- Решения эксперимента (`paper_decisions`) не пересчитываются: стратегия решает по
  игре один раз — по тому, что сайт знает в этот момент. Цена «перед началом» —
  последний снимок линии до `live_games.start_time`.
- Матч без золота (`Match.has_stats = False`, OpenDota ещё не дозаполнила) идёт в
  результаты, форму и Эло, но не в долю золота и место по фарму (`stat_games`).

## Деплой

Сайт живёт на `https://mixer-predicts.duckdns.org` (`/opt/predicatorr`, служба
`predicatorr`, порт 8100 или следующий свободный). На том же сервере есть соседи:
`pari-mixer` (сборщик данных, порт 8000 — он публикует бэкап, на котором стоит
вся модель) и органайзер `mypult` (порт 3100). Их код, конфиги nginx и
сертификаты не трогать; nginx только `nginx -t && systemctl reload nginx`,
никогда не restart. Сервер сам раз в 5 минут ставит то, что лежит в основной ветке
GitHub, поэтому всё, что туда попадает, через несколько минут уже в работе. Перед
слиянием в основную ветку — `python -m pytest` и `python -m predicator backtest`.
Если новая версия не поднимается (`/api/status` без `"ready":true` полторы
минуты), сервер откатывается и запоминает коммит в `var/bad-commit`.
Автообновление не запускает `install.sh` (только код + перезапуск), поэтому
разовые шаги настройки сервера дублируются в `update.sh` (так подключается
выгрузка pari-mixer).

## Как менять модель

1. Любую идею сначала проверить: `python -m predicator backtest` (несколько
   секунд). Протокол: признаки игроков по играм до начала кубка, обучение без
   кубка, форма и драфт только по прошлым играм. Сравнивать logloss, не только
   точность. Без заполненных таблиц `ext_*` (их качает сервер) в проверке только
   признаки лиги.
2. Параметры — `Params` в `model.py`. Подобраны на 7 кубках. Не подгоняйте их под
   ту же проверку без нужды: прибавка в третьем знаке — шум.
3. После изменения: `python -m pytest`.

## Чего нет и почему

- Матчапы/синергии по играм самой лиги, винрейт игрока на герое (в лиге и в
  рейтинге), вес ролей, поправка за сторону — проверены, не дают прибавки (см.
  README). Матчапы берутся с высокого рейтинга (STRATZ).
- OpenDota — только рейтинговая история игроков на героях; матчи лиги и так в
  бэкапе донора.
- PARI, mixer-cup, STRATZ и OpenDota доступны из песочницы только при полном
  доступе к сети; при сомнениях смотреть `/api/status` на сервере.
